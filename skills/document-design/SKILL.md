# Document design

Design a readable document around its audience and purpose. Choose a clear type hierarchy, consistent spacing, a restrained palette with adequate contrast, useful grouping, and tables or lists where they aid comparison. Prefer the user’s existing brand and layout. Avoid decorative clutter, tiny type, and unsupported asset links. Preserve facts, caveats, and content when restyling. For sales proposals, pitches, one-pagers and visual briefs, default to composed responsive static HTML when supported; follow the composition guidance in the shared workflow. Use structured blocks for ordinary text documents, explicit plain-text requests, or when static HTML is unavailable. Do not insert scripts, forms, remote trackers, or interactive controls. A designed document does not imply a PDF, slide export, or live application.

Before changing a stored document, read [SharedBrief workflow](../../references/brief-workflow.md) and preserve its current revision, access, publication state, and stable URL.

Read [the editorial design default](../../references/document-design.md) for the concrete typography, proportions and composition recipe before creating or restyling a visual document.
